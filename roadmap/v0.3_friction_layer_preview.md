# Friction Layer v0.3 (Preview)

**Status:** Preview

---

## Purpose

Kernel Core v0.2 guarantees structural integrity.

However, structural correctness alone does not explain where human evaluators experience difficulty.

v0.3 introduces a separate observation layer:

**Friction Layer**

Its purpose is to observe recurring human judgment friction without changing Kernel behavior.

---

## Position in the Architecture

```
Input
  ↓
Kernel Core v0.2
  ↓
JudgmentEvent
  ↓
Friction Layer v0.3
  ↓
Pattern Candidates
  ↓
Pattern Library
  ↓
Human Review
```

Kernel remains unchanged.

The Friction Layer operates only after a JudgmentEvent has already been emitted.

---

## Core Idea

Kernel answers:

> Is this judgment structurally valid?

Friction Layer asks:

> Where do humans repeatedly struggle while producing structurally valid judgments?

These are fundamentally different questions.

---

## What v0.3 Adds

The Friction Layer introduces four new concepts.

### CaseLog

Human-recorded observations.

Examples:

- hesitation
- forced choice
- wrong but passed
- discomfort point

CaseLog is always written by a human.

It is never inferred automatically.

---

### FrictionRecord

A normalized representation of one CaseLog entry.

```
CaseLog
    ↓
Normalization
    ↓
FrictionRecord
```

Each FrictionRecord is linked to one JudgmentEvent.

---

### FrictionSummary

Aggregated statistics across many records.

Examples include:

- hesitation rate
- forced-choice rate
- recurring primary causes
- recurring uncertainty structures
- recurring red flags

These statistics are descriptive only.

They are not quality scores.

---

### PatternCandidate

Repeated friction observations become PatternCandidates.

Examples:

- forced_asr_under_noise
- overlap_resolution_collapse
- threshold_boundary_hesitation

PatternCandidates require human review.

They are never promoted automatically.

---

## Hard Boundaries

The Friction Layer must never:

- modify Kernel behavior
- modify JudgmentEvent
- create new Red Flag IDs
- create new Primary Causes
- overwrite uncertainty
- infer human hesitation automatically
- generate governance decisions
- promote PatternCandidates automatically

Kernel remains the source of structural truth.

---

## Relationship with Kernel

Kernel detects structural violations.

Friction observes human experience.

For example:

Kernel may report:

```
PrimaryCause = PARTIAL_AUDIBILITY
```

The Friction Layer may additionally observe:

```
hesitation = true
forced_choice = true
```

Both observations are preserved independently.

---

## Relationship with UCOS

Kernel preserves structural integrity.

Friction preserves operational experience.

UCOS remains responsible for downstream governance.

```
Kernel
    ↓
JudgmentEvent
    ↓
Friction Layer
    ↓
UCOS
```

The Friction Layer never replaces UCOS.

---

## Design Philosophy

Kernel asks:

> Can this judgment be structurally justified?

Friction asks:

> Why do humans repeatedly struggle even when the structure is valid?

The first protects judgment integrity.

The second improves future evaluation systems.

---

## Future Direction

v0.3 is intended to become the observational bridge between:

- structural validation
- human evaluation behavior
- long-term pattern discovery

without weakening the deterministic guarantees established by Kernel Core.

The Friction Layer does not learn by itself.

It records.

Humans decide what should become knowledge.
